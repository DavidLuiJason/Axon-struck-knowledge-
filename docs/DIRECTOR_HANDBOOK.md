# AXON DIRECTOR HANDBOOK (read after the roadmap and the job board)

## 1. First ten minutes for a new Director
Read docs/ROADMAP.md, docs/JOB_BOARD.md, this file. Write back the items listed at the end of roadmap section 1. Open nothing else until a job needs it. Do NOT read the archives or the roadmap inside the source zip. Do not re-explain the project to the owner; the board says where things stand. If the owner brings a returned zip, inspect it (section 2). If not, take the first NOT SENT job on the board whose dependencies are MERGED and tell the owner exactly what to attach.

## 2. Inspecting a returned zip (ChatGPT or an AI Studio export)
Have: BASE.zip (the zip the builder started from), RETURNED.zip, the job code. Run:
python3 docs/director/verify_return.py BASE.zip RETURNED.zip --lane "<lane globs from the board>" --run-tests
(add --make-delta DELTA.zip for an AI Studio export). Needs python3, node and tsx (the Director sandbox also has a global `tsc`, and the script uses it to type-check in-lane src files with strict options and no project types; MEASURED 2026-10-18); it never changes the owner's files. It prints new and changed files, shrunk files, out-of-lane files, forbidden files (package.json, files.lock, guard files, .github, dictionary), nested zips, placeholder words (TODO, stub, not implemented), whether a report file exists, and with --run-tests runs every `test:kernel` command and every new test on the base and on the overlay and flags tests that got worse. It type-checks only the in-lane src files (not the project's own vite, React and Capacitor types): the cloud build is the real proof for the whole project.
Then, by hand, in this order: (1) read the report: LAW CHECK present, evidence labels honest, NOT RUN items named, unfinished items listed; (2) for each delivered engine read its exports and descriptor, read its test file headings, confirm expected values were derived independently (Python or an independent decoder), not copied from the code; (3) BREAK IT ON PURPOSE: call the engine with empty input, a huge input, odd unicode, wrong types, a boundary value; change one constant inside a COPY and confirm a test fails (a test that cannot fail proves nothing); (4) confirm no regular-expression literal appears under src/brain/mind and no new dependency in the diff; (5) for AI Studio: confirm no engine logic was copied into a screen, the screen uses the engine's limit constants, labels match the prompt, nothing claims chat control; (6) decide: INSPECTED-OK, INSPECTED-FIX (write ONE short fix prompt that quotes the exact failure), or reject (then re-plan: Two-Strike Rule, never a third try of the same fix); (7) build the merge package: the in-lane files only, plus the Director's own edits (test files, package.json test lines are listed for the owner to paste into test:kernel; or include a patched package.json ONLY if the owner asks); (8) update docs/JOB_BOARD.md (status log and job status) and give the owner the lines; (9) tell the owner the one next action.
The owner's merge steps: upload the zip to the repository TOP level; wait for Auto-unpack; then build; report the first red step.

## 3. Failure catalogue (symptom, cause, fix, prevention)
1. ChatGPT replies with only a review and a Law Check. Cause: the job felt large or the preamble ended its turn. Fix: paste the continue message that sits in the prompt file, in the SAME chat, once. Prevention: every ChatGPT prompt carries the START RULE and the continue message; jobs are sized small; if it happens twice, split the job (Two-Strike Rule), never send a third time.
2. ChatGPT stops on a missing base file. Cause: the job was sent before its dependencies were merged. Fix: merge the dependency first, send a fresh BASE.zip. Prevention: the board lists dependencies; the prompts stop on missing files by design (this is correct behaviour).
3. ChatGPT returns code that fails the type check. Fix: one fix prompt with the exact error lines. Prevention: every prompt requires `tsc --noEmit -p tsconfig.json` in its own sandbox and a report showing the result; the cloud build confirms.
4. ChatGPT delivers part of a job. Fine if the finished part is complete and tested: accept it, write a follow-up prompt for the rest (new C-number, same format). Never accept a half-built item.
5. Zip layout wrong (extra top folder, nested zip, absolute paths). The script strips one top folder and flags nested zips. Fix: ask the builder to re-zip with root-relative paths.
6. Builder touched files outside its lane. The script lists them. Fix: drop those files from the merge package (do not merge them) and say so; if the lane was wrong, fix the prompt.
7. Two jobs edit the same hot file (App.tsx, toolCatalog.ts, converter, capabilities). Prevention: engine jobs only create files; hot-file jobs run one at a time in the order on the board. Fix: merge by hand (diff3) and rerun the tests.
8. A file got shorter by more than 30 percent (script flags SHRUNK). Cause: a builder rewrote a file from memory. Fix: reject that file, restore the BASE version, ask for a minimal edit.
9. AI Studio export puts old copies of files back or drops files. Prevention: never upload a whole export; the Director compares with the BASE and uses --make-delta so only in-lane files travel. Also check the export has no fewer files than the base (the prompt tells AI Studio to stop if fewer).
10. AI Studio pushes to GitHub or edits tests, package.json, tools, .github. Prevention: the standing rules forbid it; the delta ignores out-of-lane files.
11. AI Studio screen re-implements engine logic or calls an engine wrongly. Fix: one fix prompt naming the file and the engine export to use. Prevention: the prompt tells it to read the engine's API first and never re-implement.
12. Tests are green but the screen does nothing. Cause: tests do not cover screens and do not block the cloud build. Prevention: the AI Studio prompt demands a preview run of every screen with a written report; the owner looks at the preview; the phone test list in each report.
13. Menu, registry and engines disagree. Prevention: tests/capabilityTruth.test.ts and tests/engineTruth.test.ts; after each screen merge the Director updates tests/tools.test.ts (section 4).
14. The guard refuses a merge (missing or shrunk locked file, altered dictionary file). Cause: a zip with a file that shrank by half or a missing locked file. Fix: read the guard message; never edit tools/files.lock by hand; re-send a corrected zip.
15. The roadmap exceeds 40,000 characters. Fix: compress before adding (move history to docs/archive, volatile status to the board); tests/roadmapSize.test.ts shows the count.
16. Cloud build red. Report the FIRST red step only; do not diagnose several things at once (Rule 4). Type errors: one fix prompt with the lines.
17. Secrets missing after moving the repository (AXON_DEBUG_KEYSTORE_B64, AXON_GATE): the APK is signed differently; the phone needs an uninstall. Set them again.
18. Browser preview differs from the phone. AI Studio's preview has a mouse, not a touch screen with pinch; the Android WebView differs for the clipboard, the file picker and the Back button. Every report lists phone checks for the owner; DEVICE evidence needs the phone.
19. Wrong numbers in a test (acceptance numbers remembered, not derived). Check each expected value has an independent derivation; reject otherwise.
20. The Director's own limit. Prevention: use verify_return.py instead of reading whole zips; read only the lane files; keep replies short; update the board BEFORE long work; if the limit is near, say so and give the owner the updated board lines and the next action in one message.

21. ChatGPT cannot run anything (no internet, so no tsx, no node_modules): it then delivers fewer items or unrun tests (this happened on C01: 2 of 5 engines, one failing test). Treat its tests as unverified: the Director runs them with verify_return.py. A small defect may be fixed by the Director directly (pure code, with tests whose expected values are derived independently, for example in Python); a large or unfinished part becomes a new prompt. The prompts forbid delivering fewer items because of a missing toolchain.
22. Descriptor toolId does not match the catalog id. The prompts now list the exact ids; check every descriptor against src/tools/toolCatalog.ts.

## 4. Updating tests when the menu changes
After a screen job flips tools to 'available': edit tests/tools.test.ts (the sorted comma list of available ids, counts of tools and per-group counts) and tests/capabilityTruth.test.ts if it lists tools; run both with tsx; run the whole test:kernel. When entries are removed (data-converter, text-format-converter, image-converter) lower the counts. Say exactly what changed in the merge note.

## 5. Phone test protocol
Each report lists 6 to 12 phone checks. The owner runs them on the Infinix Note 10 and replies PASS or the exact symptom per check. Only then the board marks the feature DEVICE-CONFIRMED.

## 6. Prompt-writing checklist (for new prompts)
One job; sized to what the builder was proven to carry; Standard Prompt Preamble unchanged; files that must exist; priority order; exact lane; DONE MEANS; standing rules (START RULE and continue message for ChatGPT; screen look and preview proof for AI Studio); no screens in ChatGPT prompts; no engine logic in AI Studio prompts; every expected number to be derived independently; evidence labels; test lines reported, package.json untouched; the report file path.
