## JOB C01: FIVE SMALL ENGINES

FILES THAT MUST EXIST IN THE BASE (stop if missing): src/brain/dictionary/wordBook.ts (the pattern for a safe user-data store), src/tools/engines/create/index.ts, src/tools/engines/numbers/calculator.ts, src/components/buildDetails.ts, tests/wordBook.test.ts, tsconfig.json.

PRIORITY ORDER (if you cannot finish all, deliver the first N complete):

1. LOAN. `src/tools/engines/finance/loan.ts`, test `tests/loan.test.ts`. Inputs: amount, yearly rate in percent, term (years or months), optional extra payment per month. Outputs: monthly payment, total interest, total paid, number of payments, with an extra payment also the months and interest saved, and the schedule rows (number, payment, principal, interest, balance). All money in whole cents as integers: the payment rounds to the nearest cent, each month's interest rounds to the nearest cent, the last payment adjusts so the balance ends at exactly zero, and total principal repaid equals the amount exactly. The zero-rate case works. Limits: amount up to 1,000,000,000; term up to 1,200 months; rate 0 to 100. Also export `scheduleToCsv(rows)`. Test against an independent Python Decimal calculation for at least 50 random loans plus hand-chosen edge cases (tiny amount, one-month term, zero rate, huge term, extra payment larger than the balance).
2. SPLIT AND TIP. `src/tools/engines/finance/splitTip.ts`, test `tests/splitTip.test.ts`. Bill, tip percent (0 to 100), people (1 to 100), optional "round each share up to a whole unit", optional uneven shares given as parts (for example 2 parts and 1 part). Integer cents; leftover cents go to the first people in order; the result says which; the shares always add up exactly to the total (prove for thousands of seeded random cases including round-up and uneven parts).
3. PATTERN TESTER. `src/tools/engines/code/patternTest.ts`, test `tests/patternTest.test.ts`. JavaScript regular expressions: pattern, flags g i m s u y, test text, optional replacement. Returns every match (index, text, numbered and named groups), the replaced text, and plain messages for an invalid pattern. Zero-length matches must not loop forever; limits on pattern length, text length and number of matches. Also export a pure `runWithTimeout(task, ms, runner)` abstraction where `runner` is injected (the screen will supply a Web Worker runner; the test supplies a fake one) that returns `{ ok: false, error: 'timeout' }` when the runner does not finish, so a badly backtracking pattern cannot freeze the phone. Test the timeout logic with fake runners and the engine in node.
4. DEVICE PROFILE. `src/tools/engines/device/deviceProfile.ts`, test `tests/deviceProfile.test.ts`. A pure function that turns an INJECTED environment object (user agent string, screen width and height in CSS pixels, pixel ratio, orientation, touch points, deviceMemory, hardwareConcurrency, languages, time zone, online flag, storage estimate {usage, quota}, app name, version and build) into a report: a list of {label, value} rows plus a plain-text copy. Any field the environment does not provide shows "unknown", never a guess. Parse the Android version and the WebView or Chrome version from the user agent (test with at least 10 real-looking user agent strings, including ones that carry neither). `navigator.deviceMemory` is shown as a rounded value with that note. Also export `speedProbe(now, work)` where `now` and `work` are injected, returning the milliseconds measured and a rough label; test with fake clocks.
5. TOOL STORE. `src/tools/shared/toolStore.ts`, test `tests/toolStore.test.ts`. A tiny safe store for tools that must remember something (a running timer, tally counters): `createToolStore(toolId, storage?)` with get, set, remove, exportData, eraseAll; key `axon.tool.<toolId>.v1`, a schema version inside the stored value, a size cap per tool (200 KB), safe when storage is missing, throws on read or write, or holds corrupt JSON or a newer schema version (then it returns an honest typed error and never overwrites silently). Follow the pattern of `src/brain/dictionary/wordBook.ts`. Test with fake storages in every failure mode.

LANE (the only files you may touch): NEW src/tools/engines/finance/loan.ts, src/tools/engines/finance/splitTip.ts, src/tools/engines/code/patternTest.ts, src/tools/engines/device/deviceProfile.ts, src/tools/shared/toolStore.ts, tests/loan.test.ts, tests/splitTip.test.ts, tests/patternTest.test.ts, tests/deviceProfile.test.ts, tests/toolStore.test.ts, docs/reports/C01_REPORT.md.
