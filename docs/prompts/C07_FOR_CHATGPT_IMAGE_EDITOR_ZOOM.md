## JOB C07: IMAGE EDITOR ZOOM, PAN, FULL-PICTURE VIEW (the ONLY ChatGPT job allowed to change screen files, and only the files named in its LANE; the picture's behaviour changes, the editor's LOOK does not)

CONTEXT (measured): `src/components/editors/ImageEditorScreen.tsx` (about 57 KB) draws the picture on a canvas (`canvasRef`, `bitmapRef`, `renderOps` from `ImagePipeline.ts`; canvas width and height are the rendered picture's real pixel size, so it stays sharp under CSS scaling). `CropOverlay.tsx` draws crop handles with Pointer Events over the canvas using `canvasDisplayBox`. Adjust and Filters panels draw a downscaled preview. There is NO zoom or pinch code today. R7 (a redraw fix using `bitmapVersion`) is already applied; keep it exactly.

FILES THAT MUST EXIST IN THE BASE (stop if missing): src/components/editors/ImageEditorScreen.tsx containing `bitmapVersion`, src/components/editors/CropOverlay.tsx, src/components/editors/ImagePipeline.ts, src/components/editors/MediaStrip.tsx, src/tools/imageEdit/history.ts, tests/imageEditHistory.test.ts.

WHAT THE OWNER WANTS (his words, tidied): (1) Zoom applies to the PICTURE only, never the whole interface. (2) Pinch with two fingers to zoom at any time (even before any tap) and drag to move to any part of the picture. This must have NO glitches: no jumps, no flicker, no drifting, no stuck state. (3) Tapping the picture toggles FULL-PICTURE VIEW: the picture fills the screen; tapping again goes back. Do not add double-tap zoom, buttons, or anything else not asked.

DESIGN (decided by the Director; follow it, and report anything you must change and why):
A. Pure core first, UI second. Build `src/tools/imageEdit/viewTransform.ts`: pure functions for the view state {scale, tx, ty} relative to a stage of known size and a picture of known size: fit scale (scale 1 means the whole picture fits the stage), clamp scale to [1, maxScale] where maxScale lets one picture pixel reach about 4 device pixels, bounded between 4 and 16, zoom about a focal point so the point under the fingers stays under the fingers, pan clamping so a picture larger than the stage can never leave it and a smaller one stays centred, conversion between stage points and picture points, and a function to re-fit when stage or picture size changes while keeping the centre.
B. Build `src/tools/imageEdit/gesture.ts`: a PURE state machine (reducer) over pointer events {down, move, up, cancel, wheel} with ids, positions and timestamps, producing the next view state and a list of effects (such as 'toggle-full'). Rules: one pointer on a zoomed picture pans; one pointer at scale 1 does nothing (and must not scroll the page: the stage uses `touch-action: none`); two pointers pinch AND pan together from the midpoint; a third pointer is ignored; when one finger of a pinch lifts, the remaining finger continues as a pan WITHOUT a jump (re-anchor on lift); `cancel` (the system stealing the touch) ends the gesture cleanly with no stuck state; a TAP is a single pointer released within 250 ms and moved less than 8 px, and it emits 'toggle-full'; a drag or a pinch never emits a tap; mouse wheel and ctrl+wheel zoom about the cursor (for desktop preview).
C. Build `src/components/editors/ZoomStage.tsx`: the thin React layer. It applies the transform with CSS `transform: translate3d(...) scale(...)` and `transform-origin: 0 0` on one wrapper around the canvas, updated inside `requestAnimationFrame`, with the live view state kept in a ref and written straight to the element style (NO React state update per pointer move; commit to React state only when a gesture ends). Use Pointer Events with pointer capture. The canvas is never redrawn because of zoom.
D. Full-picture view: the editor's top bar, the picture strip and the bottom tool strip slide away and the stage takes the whole screen (respect safe-area insets); tap again restores them. Zoom state is kept when toggling (the picture must not jump). If the app already handles the Android Back button (see App.tsx and any `@capacitor/app` use), Back must leave full-picture view first.
E. Interplay: switching to another picture resets to fit. A change of picture size (crop, rotate, resize) resets to fit. Undo and redo that do not change size keep the view. While the CROP panel is open, zoom and full-picture toggle are disabled and the view resets to fit when crop opens (the crop overlay's coordinates depend on an untransformed canvas; the owner may overturn this later; do not break crop). Adjust and Filters previews must zoom and pan correctly. Window resize and device rotation must re-fit without a jump. Exporting a picture must be completely unaffected by zoom.
F. Nothing else in the editor changes: no look changes, no new buttons, no new colours.

TESTS (pure, runnable with tsx): `tests/viewTransform.test.ts` and `tests/gesture.test.ts`. Cover: fit and re-fit for wide, tall, tiny and huge pictures; zoom about a focal point keeps that point fixed (check numerically); clamps at min and max; pan clamps for large and small pictures; a scripted two-finger pinch sequence; pinch then lift one finger then continue (no jump: assert the view is continuous at the lift); a pinch cancelled by `cancel`; a third pointer ignored; tap versus drag versus slow press versus tiny wiggle; pointer ids reused after up; random event sequences (at least 5,000, seeded) that must never produce NaN or Infinity, a scale outside the limits, or a picture outside the stage; wheel zoom. Also test that `ImageEditorScreen.tsx` still contains `bitmapVersion` increments at the four places R7 added them. Include every existing test in your final run (`test:kernel`).

In the report write the exact list of 8 to 10 phone checks for the owner (pinch at the picture edge, pinch while panning, lift one finger mid-pinch, fast flick, tap versus tiny drag, tap in full view, rotate the phone in full view, Back button in full view, switch pictures while zoomed, open Crop while zoomed, export while zoomed) and label everything not proven on a device as NOT RUN on device.
