## JOB C06: FILE COMPARE, ZIP, IMAGE PLAN

FILES THAT MUST EXIST IN THE BASE (stop if missing): tsconfig.json, src/tools/engines/text/textCompare.ts, src/tools/engines/create/hashChecksum.ts, node_modules or package.json listing jszip (jszip is installed and is the only library allowed, only in zipTool.ts).

PRIORITY ORDER:

1. FILE COMPARE. `src/tools/engines/files/fileCompare.ts`, test `tests/fileCompare.test.ts`. The owner wants to compare ANY two files: are they the same, and if not, how many differences and where. (a) BYTES: `compareBytes(a: Uint8Array, b: Uint8Array)` and the chunked form `compareStreams(readerA, readerB, { chunkSize: 65536, onProgress, shouldCancel })` where a reader is `{ size, read(offset, length): Promise<Uint8Array> }` (the screen will wrap Blob.slice; tests wrap arrays), so big files are never loaded whole. Result: `identical` (decided by comparing EVERY byte, never by size or hash alone), both sizes, `firstDifference` offset, `differingBytes` count, `percent`, `ranges` (start, end, length; adjacent differences merged; at most the first 1,000 listed with `moreRanges` count), and `tail` (when sizes differ, the extra bytes of the longer file are reported separately as the tail and also counted as differing). An option `stopAtFirst` for "just tell me if they are the same". `hexContext(a, b, start, length, context = 16)` returns rows for a side-by-side hex view with the differing bytes flagged. (b) TEXT: `compareText(textA, textB)` wraps `src/tools/engines/text/textCompare.ts` and ADDS positions: for each difference the line number and column in each file, plus counts of added, removed and changed lines (read textCompare.ts first and reuse it; if it cannot give line numbers, add them in your own file without editing textCompare.ts). (c) PICTURES: `comparePixels(a: {width, height, data: Uint8ClampedArray}, b, { tolerance: 0 })` on decoded RGBA data (the screen decodes with a canvas): sizes and whether dimensions match, `differingPixels`, `boundingBox` of the differences, a `diffMask` (Uint8Array, 1 where different) and an `overlay(a, diffMask)` that returns RGBA with the changed pixels highlighted; refuse more than 24 megapixels with a typed error. Limits: 200 MB per file. Tests: planted differences at known offsets (including exactly at 65,535 and 65,536 and at the very last byte), identical files, both empty, one empty, different lengths in both directions, adjacent differences merging into one range, more than 1,000 ranges, cancel in the middle, a reader that fails (typed error), pictures with planted pixel changes and with tolerance; derive expected numbers independently (Python) over at least 200 seeded random pairs. Descriptor `FILE_COMPARE_DESCRIPTOR` (toolId 'file-compare').
2. ZIP TOOL. `src/tools/engines/files/zipTool.ts`, test `tests/zipTool.test.ts`, over jszip. `createZip(files, { store: boolean })` (files = name and bytes), `listZip(bytes)` (entries: name, size, compressed size, isDirectory, encrypted flag), `extractEntry(zip, name, limits)`. SAFETY (each with a test): `validateEntryName` rejects `..` segments, a leading slash, a backslash, a drive letter, an empty name and control characters (zip-slip); caps: 5,000 entries, 200 MB total uncompressed, compression ratio 200 to 1, checked from the declared sizes AND again while inflating (an archive whose header lies must not get through: build such a zip by hand in the test); encrypted entries are detected and refused in plain words; corrupt or non-zip input gives a typed error; duplicate names after normalising are reported. Memory: extract one entry at a time. Descriptor `ZIP_TOOL_DESCRIPTOR` (toolId 'zip-tool').
3. IMAGE CONVERSION PLAN. `src/tools/engines/images/convertPlan.ts`, test `tests/convertPlan.test.ts`. The canvas work happens later in the screen; this file holds the pure decisions. `planImageConversion({ name, width, height, mime, hasAlpha?, toFormat: 'png' | 'jpg' | 'webp', quality?: number, maxSide?: number, svgWidth? })` returns the output file name (the base name kept, extension replaced, never overwriting the input name, handles dots, no extension, long and unicode names), the output mime, the output width and height after the optional maximum side (never upscaling, rounding rules stated, minimum 1), whether a white background is needed (transparent source going to JPG), the quality to use (clamped 0.05 to 1; PNG ignores it), `warnings` in plain words (metadata is dropped; JPG and WebP lose a little quality each time; SVG output is not offered), and a typed error when the input exceeds 24 megapixels (width times height) or the format is not supported. Also `supportedInputs` and `supportedOutputs` lists, and `planBatchNames(names)` making output names unique within a batch. Descriptor `IMAGE_CONVERT_DESCRIPTOR` (toolId 'converter'). Test hostile numbers (zero, negative, NaN, huge) and names.

LANE: NEW src/tools/engines/files/fileCompare.ts, src/tools/engines/files/zipTool.ts, src/tools/engines/images/convertPlan.ts, tests/fileCompare.test.ts, tests/zipTool.test.ts, tests/convertPlan.test.ts, docs/reports/C06_REPORT.md. Nothing else.
