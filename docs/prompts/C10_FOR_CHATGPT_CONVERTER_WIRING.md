CONTEXT: the Converter (`src/tools/converter/`) today has numeric kinds and Number base, with `ConverterKind.entry` of 'number' or 'text'. THE JOB (priority order):
1. DATA FORMATS kind: id 'data-formats', name 'Data formats', entry 'block' (a new entry type for multi-line text in and out; extend the type), units json, csv, tsv, yaml, xml. `convert()` gains block kinds: all formats pass through one plain-value model: JSON via `jsonTokens` (pretty-printing the JSON output with exact numbers; parse to a value with JSON.parse only after checking `validate`), CSV and TSV via `csv.ts`, YAML via `yaml.ts`, XML via `xml.ts` (its convention). Rules: JSON to CSV or TSV needs an array of objects (a single object becomes one row; anything else is a typed error saying so); columns are the union of keys in first-seen order; nested objects flatten with dot paths; arrays inside cells are written as JSON text and the result says so; CSV or TSV to JSON keeps text as text unless the option `detectTypes` is on; JSON to XML needs a single root key (or the `rootName` option). Every result carries `changes: string[]` in plain words (for example "comments were dropped", "arrays inside cells were written as text"). Same format to same format returns the input (reformatted for JSON).
2. TEXT FORMATS kind: id 'text-formats', name 'Text formats', entry 'block', units txt, md, html, via `convertTextFormat`, passing `changes` through.
3. IMAGE kind: id 'image', name 'Image', entry 'file' (a new entry type; extend the type), units png, jpg, webp as targets and png, jpg, webp, gif, bmp, svg as inputs; the engine side holds only the pure planning through `planImageConversion` (the canvas work happens in the screen layer later). Expose `planConversion(request)`.
4. Keep ALL existing kinds and results byte-for-byte identical (the existing converter tests must pass unchanged). Update `convert()`'s return type compatibly (existing callers keep working: check `src/components/ConverterScreen.tsx` compiles unchanged by running the type check).
5. TESTS `tests/convertBlocks.test.ts`: every pair of the five data formats (20 pairs) on at least 20 seeded random values each, expected values derived independently where an independent path exists (Python json, csv, xml.etree), the typed errors, the `changes` notes, the text format pairs, the image plans, and a regression that existing kinds give identical results to a recorded table you compute from the BASE before changing anything.
