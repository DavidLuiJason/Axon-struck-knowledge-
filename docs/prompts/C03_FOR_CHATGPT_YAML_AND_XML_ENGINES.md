## JOB C03: YAML AND XML ENGINES

FILES THAT MUST EXIST IN THE BASE (stop if missing): tsconfig.json, src/tools/engines/text/index.ts.

Both engines work on PLAIN VALUES (the JavaScript values JSON can hold: null, boolean, number, string, array, object) so other jobs can connect them without sharing code. They return typed results; they never throw.

PRIORITY ORDER:

1. YAML SUBSET. `src/tools/engines/data/yaml.ts`, test `tests/yaml.test.ts`. `parseYaml(text)` and `stringifyYaml(value, { indent: 2 | 4 })`. Supported: block mappings, block sequences (including a sequence of mappings), plain strings, single- and double-quoted strings (with the YAML escapes), integers, floats, true and false (only the lower-case forms), null and `~`, comments, flow lists `[a, b]` and flow maps `{a: b}`, `|` and `>` block scalars (with chomping `-` and `+`), and a single document with an optional leading `---`. Everything else is REFUSED with a typed error that names the line and what is unsupported: anchors, aliases, tags, several documents, complex keys, tabs used for indentation, merge keys. The writer quotes whenever a plain string could be misread (for example yes, no, on, off, null, ~, true, numbers, a leading dash, a colon, a hash, empty string, leading or trailing spaces) and round-trips. Limits: 1 MB, depth 100, 100,000 values. Test over at least 300 seeded random values: `parseYaml(stringifyYaml(v))` equals v; plus hand-made YAML documents whose expected values you derive independently (use Python with PyYAML if it is installed in your sandbox, otherwise by hand, and say which); plus hostile inputs (very deep nesting, a billion-laughs style alias attempt must be refused as an alias, long lines, odd unicode, CRLF).
2. XML. `src/tools/engines/data/xml.ts`, test `tests/xml.test.ts`. `parseXml(text)` returns a plain value and `writeXml(value, { indent, rootName? })` writes it, using this convention (state it at the top of the file and in the report): attributes go under keys starting with "@", text content under "#text", repeated sibling elements become an array, an element with only text becomes the string, an empty element becomes "" (and `null` is written as an empty element). Supported: elements, attributes (single and double quotes), text, CDATA (read as text), comments and processing instructions (dropped, and the result says so in a `notes` list), the five predefined entities and numeric entities, self-closing tags, an XML declaration, namespaces kept as plain prefixed names. REFUSED with a line and column: a DOCTYPE or any entity definition (this blocks entity-expansion attacks, test it), mismatched or unclosed tags, duplicate attributes, characters not allowed in XML. Limits: 1 MB, depth 100, 100,000 nodes; explicit stack, no recursion that can overflow. Test over at least 300 seeded random values built from the convention (so the round trip must hold: write then parse equals the original) plus hand-made documents with independently derived expected values (Python's xml.etree is allowed for checking), plus hostile inputs.

LANE: NEW src/tools/engines/data/yaml.ts, src/tools/engines/data/xml.ts, tests/yaml.test.ts, tests/xml.test.ts, docs/reports/C03_REPORT.md. Nothing else.

DONE MEANS: both engines pass their tests, the type check and the whole `test:kernel`; the report states the XML convention and the exact YAML subset; the report lists the test lines to add.
