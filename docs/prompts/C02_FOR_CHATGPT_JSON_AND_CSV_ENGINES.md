## JOB C02: JSON AND CSV ENGINES

FILES THAT MUST EXIST IN THE BASE (stop if missing): tsconfig.json, src/tools/engines/text/index.ts, tests/tools.test.ts.

PRIORITY ORDER:

1. JSON TOKENS AND REFORMAT. `src/tools/engines/data/jsonTokens.ts`, test `tests/jsonTokens.test.ts`. A hand-written JSON tokenizer and reformatter built on a TOKEN STREAM, not on JSON.parse and JSON.stringify, so that number literals (like 1.0, 1e5, 12345678901234567890), key order and duplicate keys are preserved exactly. Exports: `tokenize(text)`, `pretty(text, { indent: 2 | 4 | 'tab', sortKeys?: boolean })`, `minify(text)`, `validate(text)`. Errors carry line and column (1-based) and a plain message (unexpected character, unterminated string, trailing comma, bad escape, bad number, text after the value, empty input). Strict JSON (RFC 8259): no comments, no trailing commas. Limits: 2 MB of text, nesting depth 200 (an honest typed error, never a stack overflow: use an explicit stack, not recursion). Properties to test over at least 300 seeded random documents: `minify(pretty(x)) === minify(x)`, `pretty(pretty(x)) === pretty(x)`, and the parsed value (JSON.parse) is equal before and after whenever the numbers are exactly representable; plus a hostile set (deep nesting, huge strings, lone surrogates, BOM, CRLF, empty arrays and objects, unicode escapes).
2. JSON VIEW MODEL. `src/tools/engines/data/jsonView.ts`, test `tests/jsonView.test.ts`. Pure data for a collapsible tree: `buildTree(text)` returns a root node with lazy children: `childrenOf(node, offset, limit)` so a 100,000-item array is never expanded at once (at most the requested window, default 500, with the remaining count). Each node has type, key, a short preview (long strings clipped with the full length known), size (items or keys), and its path in `data.items[3].name` style (keys that are not plain identifiers use `["the key"]`). Also `stats(text)` (depth, number of values, number of keys, size in bytes) and `findPath(root, path)`. Build on jsonTokens.ts (exact number text kept). Limits as above.
3. CSV AND TSV. `src/tools/engines/data/csv.ts`, test `tests/csv.test.ts`. `parseCsv(text, { delimiter: ',' | '\t' | ';', header: boolean, detectTypes?: boolean })` and `writeCsv(rows, { delimiter, header })`. RFC 4180: quoted fields, doubled quotes, embedded delimiters and line breaks, CRLF and LF, a final line break optional, a BOM tolerated. Rows of different length are reported with the row number (a warning list), never silently padded. `detectTypes` turns exact numbers, true, false, null into values and leaves everything else as text. Writer quotes exactly when needed and round-trips. Limits: 1 MB of text, 100,000 rows, 1,000 columns. Properties over at least 300 seeded random tables including quotes, commas, line breaks and emoji: `parseCsv(writeCsv(x))` equals x. Also export `rowsToObjects` and `objectsToRows` (the union of keys in first-seen order, missing cells empty).

LANE: NEW src/tools/engines/data/jsonTokens.ts, src/tools/engines/data/jsonView.ts, src/tools/engines/data/csv.ts, tests/jsonTokens.test.ts, tests/jsonView.test.ts, tests/csv.test.ts, docs/reports/C02_REPORT.md. Nothing else. Export `JSON_VIEW_DESCRIPTOR` from jsonView.ts.
