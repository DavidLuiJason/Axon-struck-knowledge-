## JOB C04: TEXT FORMATS AND FILE INSPECTOR

FILES THAT MUST EXIST IN THE BASE (stop if missing): tsconfig.json, src/tools/engines/text/index.ts, src/tools/engines/create/hashChecksum.ts.

PRIORITY ORDER:

1. MARKDOWN. `src/tools/engines/text/markdown.ts`, test `tests/markdown.test.ts`. `markdownToHtml(text)` and `markdownToText(text)`. Supported: headings (# and underline style), paragraphs, bold, italic, inline code, fenced and indented code blocks, block quotes, ordered and unordered lists (nested), links, images (written as a link with the alt text only, never loaded), horizontal rules, hard line breaks, backslash escapes. SECURITY (each with tests): raw HTML inside Markdown is ESCAPED and never passed through; links whose address starts with javascript:, data:, vbscript: (any letter case, with embedded tabs or line breaks or entities) are refused and written as plain text; all text and attribute values are escaped. Limits: 1 MB; nesting depth 50 (explicit, no stack overflow). Test against at least 60 hand-made cases whose expected HTML you derive independently (CommonMark examples you know are fine, but derive the expected output by reasoning and say so; you may use Python `markdown` or `commonmark` if present in your sandbox and say which), plus 300 seeded random strings that must never throw and never emit an unescaped `<script`.
2. HTML TO TEXT AND MARKDOWN. `src/tools/engines/text/htmlText.ts`, test `tests/htmlText.test.ts`. `htmlToText(html)` and `htmlToMarkdown(html)` using a hand-written tokenizer (there is no DOMParser under tsx). script, style and head content dropped; entities decoded (named common ones and numeric); headings, paragraphs, line breaks, lists (nested), links, images (alt text), bold, italic, code, pre, block quotes, tables as simple rows of cells separated by " | "; malformed HTML (unclosed, misnested tags) handled without throwing or hanging; nothing is ever executed. Limits as above. Tests: derive expected outputs independently; hostile inputs (unterminated tags, comments, huge attribute values, deep nesting).
3. TEXT FORMAT HUB. `src/tools/engines/text/textFormats.ts`, test `tests/textFormats.test.ts`. `convertTextFormat({ from, to, input })` for from and to in txt, md, html: txt to html (escape, paragraphs, line breaks), txt to md (escape Markdown specials), md to html, md to txt, html to md, html to txt, and same to same returns the input. The result carries a `changes: string[]` list of plain-words notes about what was lost or changed (for example "images became links", "raw HTML was escaped"). Export `TEXT_FORMATS` (the three ids with display names) and `TEXT_FORMAT_LIMITS`. Descriptor `TEXT_FORMATS_DESCRIPTOR`.
4. FILE INSPECTOR. `src/tools/engines/files/inspect.ts`, test `tests/fileInspect.test.ts`. `inspectBytes({ name, size, head: Uint8Array })` where `head` is up to the first 4,096 bytes (the screen reads the rest in chunks). Returns: guessed type from magic numbers (at least PNG, JPEG, GIF, WebP, BMP, ICO, TIFF, PDF, ZIP (and docx, xlsx, pptx, apk, jar as ZIP kinds by name), GZIP, 7z, RAR, TAR, MP3 (ID3 and frame sync), MP4 and MOV (ftyp), WAV, OGG, FLAC, SQLite, ELF, Windows EXE, Java class, plain text, unknown), whether the file name extension agrees (and says so plainly), text detection with a guessed encoding (UTF-8, UTF-8 with BOM, UTF-16 LE or BE, otherwise "binary or unknown") with the fraction of control bytes, picture width and height parsed from the header bytes for PNG, JPEG (scan the segments for SOF), GIF, WebP (VP8, VP8L, VP8X) and BMP, a hex dump of the first 256 bytes (offset, 16 hex bytes, ASCII) and a function `hexDump(bytes, offset, length)`. Also `describeSize(bytes)` giving "1.5 MB (1,572,864 bytes)" style text with binary units explained. Descriptor `FILE_INSPECT_DESCRIPTOR`. Test with real minimal sample files you generate in the test with Python-derived byte arrays (one valid tiny file of every type you claim to detect), truncated and corrupt headers, empty input, and random bytes (must never throw).
